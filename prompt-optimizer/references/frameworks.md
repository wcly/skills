# Prompt Framework Reference

## Selection Table

| Framework | Best for | Typical signals | What usually matters most |
| --- | --- | --- | --- |
| `CRISPER` | 通用型高质量任务提示词 | “帮我把这个 prompt 写专业一点”“给我一个更完整的提示词” | 角色、背景、任务定义、输出格式 |
| `BROKE` | 结果导向、计划、目标拆解 | 学习计划、OKR、路线图、阶段目标、关键结果 | 明确目标、关键结果、评估与迭代 |
| `CO-STAR` | 文案、营销、内容创作 | 微博、小红书、邮件、广告、宣传语、品牌表达 | 受众、风格、语气、说服力 |
| `SCOPE` | 复杂问题、破局方案 | “不知道怎么做”“预算有限”“竞争激烈”“要边做边评估” | 情景、障碍、行动方案、复盘 |

优先选择最能服务用户成功标准的框架，而不是看表面关键词。

## CRISPER

### Best fit

- 通用任务增强
- 需要补齐角色、背景、任务、格式
- 用户目标相对明确，但 prompt 写得太短或太散

### Template

```text
你是[角色/能力定位]。

背景信息：
[相关上下文、对象、限制、已有信息]

任务：
[清晰、具体地说明要完成什么]

风格与表达要求：
[专业/简洁/口语化/严谨/适合初学者等]

输出要求：
[列表/表格/Markdown/JSON/代码/步骤说明]

约束条件：
[必须包含什么、避免什么、长度限制、边界条件]

请先确保输出满足目标、约束和格式要求；如果存在明显歧义，请给出最合理的处理方式。
```

### Example

原始需求：

```text
帮我写一个减脂食谱 prompt
```

优化方向：

- 补角色：营养师、健康教练
- 补上下文：年龄、性别、饮食习惯、禁忌
- 补结果：按天、按餐次、表格输出
- 补约束：食材易买、符合中国饮食习惯

## BROKE

### Best fit

- 学习计划
- 目标拆解
- 路线图、阶段计划、OKR 风格任务
- 强调结果和可衡量产出的请求

### Template

```text
背景：
[为什么要做这件事，当前基础，适用场景]

角色：
[资深导师/顾问/教练/规划师]

目标：
[最终要达到什么结果]

关键结果：
[2-5 个可衡量结果，包含数量、阶段或验收方式]

迭代与优化：
[如何复盘、多久检查一次、如何调整]

请输出一个结构清晰、可执行的方案，并明确每个阶段的行动项、产出物和评估方式。
```

### Example

原始需求：

```text
帮我做一个 AI 产品经理学习计划
```

优化方向：

- 补起点：当前经验、可投入时间
- 补目标：多少周、达到什么水平
- 补关键结果：完成几个项目、产出什么作品
- 补复盘：每周或每月评估

## CO-STAR

### Best fit

- 社交媒体文案
- 广告、品牌表达
- 需要考虑语气、情绪和目标受众的内容创作

### Template

```text
背景：
[产品/品牌/场景/素材]

目标：
[这段内容要促成什么行动]

风格：
[参考谁的风格、写作方式、结构特点]

语气：
[温暖/热情/克制/专业/高端/真诚]

受众：
[目标人群及其关注点、顾虑、偏好]

输出：
[文案类型、长度、结构、是否带标题/标签/CTA]

请写出符合目标受众的内容，并确保语言有代入感、行动引导明确、不过度空泛。
```

### Example

原始需求：

```text
帮我写一个微博推广文案
```

优化方向：

- 补产品和卖点
- 补转化目标：点击、私信、购买、关注
- 补受众：宝妈、学生、职场人等
- 补语气：温柔、可信、兴奋、专业

## SCOPE

### Best fit

- 用户不知道怎么开始
- 问题存在预算、资源、竞争或时间限制
- 需要行动计划和后续评估

### Template

```text
情景：
[当前处境、任务背景]

计划难点：
[限制条件、复杂因素、风险]

目标：
[希望达到的结果]

行动方案：
[按步骤给出可执行方案]

评估：
[如何观察结果、何时复盘、如何调整]

请给出一个现实可执行的方案，并说明每一步的目的、风险和调整条件。
```

### Example

原始需求：

```text
我们要推一个新产品，预算有限，怎么办
```

优化方向：

- 补市场环境和资源条件
- 补时间窗口和销售目标
- 补团队资源与渠道
- 补复盘节奏和调整依据

## Universal Upgrades

无论选哪个框架，都可以按需加入下面这些增强项：

- `示例`
  当输出风格或结构要求很高时，补一个参考示例或风格参照
- `限制输出范围`
  明确长度、必须包含项、禁止项、适用边界
- `任务分解`
  对复杂任务要求分步骤思考或分阶段产出
- `自检`
  要求模型在输出前快速检查是否满足目标、格式和约束
- `多版本`
  当方向不够明确时，要求模型给出 2-3 个不同风格或策略版本

## Decision Heuristics

如果一个需求同时像多个框架，按下面顺序判断：

1. 首先看用户最终想要的“成功结果”是什么。
2. 如果是“打动某类人并促成行动”，优先 `CO-STAR`。
3. 如果是“达到某个可衡量目标”，优先 `BROKE`。
4. 如果是“在复杂限制下找到可执行方案”，优先 `SCOPE`。
5. 其余大多数通用增强请求，优先 `CRISPER`。
